# 근거 변경과 모델 교체 실험

[실제 데모](https://sokldjs554.github.io/recheck-ml-serving/)에서 **근거 변경 실험**을 선택합니다.
이 화면은 실제 Python API를 사용합니다. 기존 송금 판단 화면의 브라우저 시뮬레이션과 별도 세션입니다.

## 무엇을 보여주는가

답변을 만들 때 맞았던 근거가 사용할 때도 맞는지 확인합니다. 문서 내용을 바꾸면
저장된 답변을 덮어쓰지 않고 인용 버전과 현재 문서의 차이를 확인합니다.
모델 교체도 동일한 원칙을 따릅니다. 모델과 인덱스가 맞고, 실제 검색 평가를 통과한
묶음만 활성화합니다. 두 제품(상담 초안, 업무 체크리스트)이 같은 API와 SDK를 재사용합니다.

1. **실험 시작 → 답변 준비**: `하루 이체 한도`를 검색하면 가상 문서의 `300만 원`을 인용합니다.
2. **지금 사용해도 되는지 확인**: 현재 문서와 배포 버전, 120초 만료를 검사합니다.
3. 원문을 `하루 이체 한도는 100만 원입니다. 송금 본인 인증이 필요합니다.`로 수정합니다.
4. 같은 답변을 다시 검증하면 `source_changed`로 거절합니다. 삭제는 `source_deleted`입니다.
5. **후보 평가**에서 모델만 교체한 후보 또는 질문을 구분하지 못하는 후보를 선택합니다.
   실제 검색 결과와 시간이 기록되고, 실패한 후보의 적용 버튼은 비활성화됩니다.
6. 정상 후보를 평가하고 **검증된 모델·인덱스 적용**을 누릅니다. 새 답변은 `100만 원`을 인용합니다.
7. 업무 체크리스트로 전환해 같은 검색·기록·재검증 흐름을 확인합니다.

## 실제 구현

- 어휘 기반 **문자 2~4-gram TF-IDF + cosine search**입니다. 학습한 vocabulary/IDF,
  좌표 변환 규칙, 문서 벡터, 원문·버전을 JSON으로 직렬화합니다. pickle이나 임의 실행 코드는 받지 않습니다.
- 정상 v2 모델은 좌표 순서를 뒤집습니다. v1 인덱스도 같은 차원이므로 shape 검사로는
  불일치를 찾을 수 없습니다. 모델 파라미터·좌표 규칙 해시와 인덱스가 요구하는 모델 해시를 비교합니다.
- 품질 실패 후보는 모든 문서를 같은 벡터로 인코딩하도록 의도적으로 망가뜨립니다.
  일치 검사만 통과해도 실제 순위가 나빠지면 Recall@1 게이트에서 차단됩니다.
- 모든 문서는 가상이며 실제 은행 정책·고객 정보가 아닙니다. 출력은 **근거 발췌와 결정적인
  체크리스트 템플릿**입니다. LLM이 생성하거나 진위를 보장한 답변이 아닙니다.

## 평가와 배포 경계

| 기준 | 이 프로젝트의 설정 |
|---|---|
| 모델과 인덱스 | 모델 해시 일치 + 전체 아티팩트 내용 해시 |
| 검색 품질 | Recall@1 ≥ 0.90 |
| 품질 하락 | 동일한 현재 문서 집합의 기본 TF-IDF 기준선보다 0.05 이하 하락 |
| 검색 시간 | 워밍업 후 p95 ≤ 50ms |
| 평가 데이터 | 문서 4개, 고정 질문 8개를 3회 반복. 삭제한 문서의 질문 제외 |

이 숫자는 토스뱅크 SLA가 아닙니다. 24개 시간 표본은 24개의 독립된 질문도 아닙니다.
검색 시간에는 HTTP·DB·아티팩트 학습이 포함되지 않습니다. 평가 시점의 호스트 부하로
시간 게이트가 실패할 수 있으며, 수치를 고정하거나 실패를 성공으로 바꾸지 않습니다.
데모용 작은 개발 fixture이므로 공개 검색 품질이나 미지 질문 일반화를 입증하지 않습니다.

평가 보고서는 서버가 만든 불변 기록입니다. 클라이언트는 점수나 `passed`를 제출하지 않습니다.
보고서의 corpus hash, 기준 배포 epoch, 재구성한 artifact hash를 적용 직전에 다시 확인하고
한 트랜잭션에서 전체 묶음을 교체합니다. 평가 후 원문이 바뀌거나 다른 후보가 먼저 배포되면
보고서가 통과했어도 적용을 거절합니다. 현재 기능은 **배포 전 검증**이며 온라인 카나리 트래픽,
운영 품질 저하 자동 감지/자동 롤백을 구현했다고 주장하지 않습니다.

## 저장·동시성·한도

기존 PostgreSQL/SQLite Store를 사용합니다. 세션 행 잠금으로 쓰기를 직렬화하되 검색과
평가는 잠금 밖에서 수행하고, 기록/적용 직전에 스냅샷을 재확인합니다. PostgreSQL에서는
여러 API 인스턴스가 같은 상태를 읽습니다. SQLite는 공개 단일 인스턴스 데모용입니다.

문서 이벤트는 실제 본문과 revision을 포함합니다. 동일한 최신 이벤트 재전송은 no-op,
더 오래된 revision과 같은 revision의 다른 내용은 409입니다. 삭제 후 늦게 도착한 수정이
문서를 되살리지 못합니다. 더 높은 revision의 명시적 수정은 복구로 허용합니다.

문서 4개/본문 600자, 기록 40개, 평가 20개, 최근 이벤트 20개로 제한합니다. 기존 세션
1시간 만료/1,000개 상한과 삭제 cascade를 따릅니다. 한도 도달 시 새 실험을 시작합니다.
평가는 프로세스당 동시 2개/대기 4개이며 취소된 작업도 종료 전까지 슬롯을 차지합니다.
이 한도는 공유 분산 rate limiter나 인증을 대체하지 않습니다.

문서 하나의 변경은 그 문서를 인용한 답변만 무효화합니다. 다만 새로운 검색은 인덱스가
현재 문서와 일치할 때까지 차단합니다. 모델·인덱스 배포 교체는 이전 배포의 모든 기록을
무효화합니다. 사용 확인은 **확인 시점의 유효성**이며 외부 송금·업무 실행과 원자적으로
묶이지 않습니다. 다른 작업까지 보장하려면 해당 시스템 안의 트랜잭션/명령 프로토콜이 필요합니다.

## 공통 SDK 실행

```bash
# 먼저 로컬 서버 실행: backend/.venv/bin/python scripts/serve_demo.py
PYTHONPATH=backend backend/.venv/bin/python examples/answer.py http://localhost:8000
PYTHONPATH=backend backend/.venv/bin/python examples/checklist.py http://localhost:8000
```

두 예제는 `recheck.sdk.EvidenceClient`의 `prepare(..., product=...)`와 `validate(receipt_id)`를
사용합니다. httpx client의 수명·인증·timeout은 호출자가 소유하고 HTTP 실패는 예외로
전파합니다. 오래된 기록을 유효한 대체 결과로 사용하지 않습니다.
브라우저는 TypeScript HTTP 어댑터로 같은 서버 API를 호출합니다.
