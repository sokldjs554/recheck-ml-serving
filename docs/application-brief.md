# RECHECK — AI 결과의 최신성을 실행 시점까지 검증하는 Python 백엔드

**Python·LLM·AI/ML 경험이 있는 신입으로서, 모델을 호출한 이후의 실패와 서버의 보장 범위에 관심을 둔 AI 협업 프로젝트입니다.**

[실제 API 데모](https://sokldjs554.github.io/recheck-ml-serving/) · [GitHub](https://github.com/sokldjs554/recheck-ml-serving) · [핵심 코드](../backend/recheck/evidence.py) · [실험 원본](evidence/safety-evaluation.json)

## 해결하려는 문제

모델이 답변을 만들 때 맞았던 정보가 사용할 때는 바뀔 수 있습니다. 상담 문서의 한도가
300만 원에서 100만 원으로 바뀌어도 이미 준비된 답변에는 300만 원이 남습니다.
또한 사용 직전에 확인하더라도 확인과 작업 기록 사이에 변경이 끼어들 수 있습니다.
RECHECK는 이 차이를 실제 API 데모에서 재현하고, 내부 작업 기록이 오래된 근거를 사용하는 것을 차단합니다.

## 기술적 선택과 검증

| 판단할 문제 | 구현한 선택 | 확인한 근거 |
|---|---|---|
| 확인 직후 근거가 바뀌면? | 문서 변경과 같은 세션 잠금을 사용해 검증·내부 작업 기록을 한 SQL 트랜잭션으로 처리 | SQLite·PostgreSQL에서 같은 9개 사건 순서 비교. 오래된 결과 6건 중 생성 결과 신뢰는 6건, 별도 확인은 5건 허용했고 원자적 기록은 0건 허용 |
| 요청이 성공했는데 응답을 잃으면? | 같은 요청 키는 불변 작업 ID를 반환하고, 다른 답변에 키를 재사용하면 거절 | 실제 SQL 연결의 동시 제출·재시도 테스트, 데모의 동일 ID 반환과 작업 수 확인 |
| 무거운 추론이 API를 막으면? | 별도 모델 프로세스, 제한된 실행·대기 수, 취소 뒤에도 실행 중인 CPU 작업의 슬롯 유지 | [CPU 비교](compute-experiments.md)에서 응답성·시간 내 성공·거절·메모리를 함께 측정. 분리의 메모리 비용과 불리한 결과도 공개 |

모델·인덱스 묶음의 배포 전 평가, OpenTelemetry 추적, Kubernetes 장애·복구 실험도 제공합니다.
[공고 항목별 실행 근거](job-coverage.md)에서 필요한 부분을 선택해 확인할 수 있습니다.

## 토스뱅크에서 기여하고 싶은 방향

Python·LLM·AI/ML 경험을 바탕으로, AI 제품을 만드는 팀들이 공통으로 필요로 하는
최신성 검증, 시간 예산, 장애 분류와 추적을 재사용 가능한 서버 기능으로 만드는 데 기여하고 싶습니다.
AI와 개발하면서 반복되는 오류를 직접 조사하고 서로 다른 해결책을 비교했던 경험을,
실패 재현과 측정 근거를 남기는 개발 방식으로 발전시키고자 합니다.

**기술:** Python · FastAPI · SQLAlchemy · PostgreSQL · scikit-learn · OpenTelemetry · Docker/Kubernetes · React/TypeScript

**개발 방식과 범위:** AI와 협업해 제작한 포트폴리오입니다. 사용자 제공 경험·피드백과 AI 지원 구현·검증을 구분합니다.
데모는 가상 문서의 TF-IDF 검색과 내부 SQL 작업 기록이며 실제 메시지·송금, LLM 생성, 장기 SLA·실사용 성과를 주장하지 않습니다.
비교 수치는 고정 사건의 반례 검증이며 일반 사고율이나 금융 서비스 안전성으로 환산하지 않습니다.
