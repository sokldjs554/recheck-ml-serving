## 1. 공개 실행에서 저장과 응답을 구분하는 판단

- **발생 조건:** 실행 후 응답이 끊기거나 늦어져도 SQL 저장은 끝날 수 있다. 기존 HTTP 지표는 호출 수를 세지만 상담 execute 업무 결과와 저장 단계는 구분하지 않았다.
- **재현·관측:** 실제 SQL lock을 잡고 경쟁 요청을 보내면 503, SQL UPDATE 실패에는 저장된 작업이 없다. 반면 UPDATE 시점에 HTTP 연결을 끊고 작업을 풀면 commit 후 같은 키 요청에서 같은 작업이 반환된다.
- **코드·원인:** 기존 `BUSINESS_ROUTES`는 decisions/infer만 포함했다. sync execute는 별도 작업 스레드에서 실행돼 HTTP task 취소와 SQL 작업 종료가 같지 않다.
- **검토한 방법:** HTTP 응답만 파싱하면 수신 실패 때 저장 결과가 사라진다. DB 스키마에 모든 관측을 추가하면 기존 트랜잭션의 쓰기 비용·복잡도를 늘린다.
- **선택:** 현재 트랜잭션 밖의 실행 관측 wrapper, 내부의 단계 span, 별도의 HTTP 종료 관측을 연결했다. 작업 ID는 commit 성공 후 기록한다. 값이 늘어나는 식별자는 로그/trace에만 넣고, DB commit 결과 불명은 `unknown`으로 남긴다.
- **수정 후 검증:** 실제 잠금 경쟁, 쓰기 실패, ASGI 취소, 실제 소켓 종료 후 SQL 저장과 같은 키 회복을 검사했다. 코드 검토에서 발견한 디스패치 대기 누락도 middleware 진입 시간으로 수정했다.
- **해석 범위:** 15초 관측 기준은 강제 취소나 네트워크 왕복 SLA가 아니다. 앱의 flush/commit 구간을 DB 엔진 고유 시간으로 해석하지 않는다. [재현 명령·코드·근거](evidence-execution-observation.md).

## 2. 완료 복원에 존재하지 않는 버튼을 안내한 문제

- **조건·재현:** 전체 실행 완료 → 같은 탭 새로고침. 작업과 로그는 보존되지만 ‘이어서 실행’ 안내가 나왔다. 완료 상태에서는 해당 버튼이 없거나 비활성화되어 있었다.
- **원인:** `CaseStudy.tsx`가 `restored` 여부만 검사하고 단계와 무관한 안내를 표시했다. `CaseRunButton.tsx`는 이미 6단계 완료를 구분했다.
- **선택지:** 완료 상태에도 불필요한 재실행 버튼을 만들거나, 복원 안내를 실제 상태에 맞출 수 있었다. 후자를 선택해 자동 요청·새 세션을 추가하지 않았다.
- **변경:** 중간 상태는 실제 이어서 실행 버튼, 완료 상태는 저장된 차단 결과와 작업 ID, 만료 상태는 처음부터, 재준비가 필요한 상태는 새 답변 준비로 안내한다. 로그에는 브라우저에서 복원한 과거 응답임을 표시한다.
- **검증:** 완료·중간 안내 렌더링 검사, 실제 API 완료 후 reload 무요청, commit 응답을 보류한 상태에서 reload 후 같은 키 재시도, 화면 이동·세션 만료·명시적 초기화를 검사했다.
- **직접 재현:** `npm --prefix demo test`; 공개 데모에서 전체 과정 실행 → 새로고침. 중간 상태는 한 단계씩 실행한 뒤 새로고침. [브라우저 자동 검사](../scripts/check_restoration_browser.py).

## 5. 제출 문서에 반영할 사실

- 프로젝트 구현: 공개 상담 실행의 결과·저장 단계 관측, 응답 취소 후 저장/재시도 확인, 완료·중간 복원 안내 수정, 명사형 제목과 실제 시연 갱신.
- 성능: 과거 180초 실험의 목표 투입량 120건/s와 유효 처리량 67.56·67.65건/s를 분리한다. 이번 기능 검증을 처리량 재측정으로 쓰지 않는다.
- 범위: 공개 TF-IDF 상담은 `/evidence/.../execute`, CPU 모델 실험은 `/decisions`. 준비한 장애 사례의 결과를 운영 사고율로, 단일 노드 kind 복구를 상용 고가용성 경력으로 바꾸지 않는다.
- 본인 역할: AI와 주제 후보를 비교하고 방향을 결정, 기능·수정 요구와 구체적 예시 제시, 결과 검토. 코드·데모 작성은 AI가 주로 담당했다는 기존 설명을 유지한다. 위 사례는 지원자가 재현·이해할 기술 자료이며 직접 구현 경험을 확인한 진술이 아니다.

이 문서는 자소서·포트폴리오를 대필한 문서가 아니라 해당 문서에 반영할 구현 사실과 재현 근거다.
