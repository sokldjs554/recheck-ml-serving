# 친구 대상 사용성 점검

상태: **지인 1명의 사후 답변 수신 · 수정 후 재확인 대기** (2026-10-19). 행동 순서·기기·도움 여부는 미기록이다. [전달받은 답변과 수정](usability-feedback-2026-10-19.md#작업-흐름-재구성). 아래 양식은 다음 관찰에서 사용한다.
브라우저 자동 검사·AI 검토·개발자의 화면 확인은 사람의 관찰 결과로 세지 않는다.

## 진행자 준비

- 프로젝트를 처음 보는 친구에게 10분 정도 요청한다. 이름 대신 P01, P02처럼 구분한다.
- [공개 데모](https://sokldjs554.github.io/recheck-ml-serving/#case)를 전달한다. 기능 설명·시연 영상·이 문서의 관찰 기준은 먼저 보여주지 않는다.
- 첫 화면에 과거 기록이 남지 않은 새 탭에서 시작한다. 같은 탭을 과제 3까지 유지한다. 기록 양식에 코드/배포 버전을 적는다.
- 시작 전에 “당신을 평가하는 것이 아니라 화면에서 막히는 곳을 찾는 점검입니다. 보이는 것과 생각을 편하게 말해주세요. 언제든 중단해도 됩니다.”라고 설명한다.
- 녹화는 필수가 아니다. 동의한 경우에만 사용한다. 계정·실명·연락처를 기록하지 않는다.

## 참여자에게 읽어줄 과제

**1. 첫 화면 이해**

“이 페이지를 처음 봤다고 생각하고 살펴봐 주세요. 어떤 문제를 다루는 프로젝트로 보이는지, 여기서 무엇을 해볼 수 있을지 본인 말로 설명해 주세요.”

**2. 체험과 결과 이해**

“이 프로젝트가 제공하는 대표 체험을 직접 진행해 주세요. 끝났다고 생각하면 어떤 일이 일어났는지, 그렇게 판단한 화면의 근거를 설명해 주세요.”

**3. 새로고침 후 이전 기록 확인**

“방금 체험한 페이지를 새로고침해 주세요. 이전에 진행한 내용을 다시 확인하고, 지금 화면에서 알 수 있는 내용을 설명해 주세요.”

버튼 이름·위치·정답·기대되는 결과를 미리 알려주지 않는다. 과제 2를 완료하지 못했다면 대신 조작하지 말고 과제 3을 ‘미진행’으로 남긴다. 부분 진행 상태에서 과제 3을 했다면 그 상태를 명시한다.

## 진행 중 관찰

진행자는 조용히 보고, 참가자가 멈춰도 바로 대신 누르지 않는다. 필요하면 “지금 무엇을 하려고 했나요?”, “어떤 일이 일어날 것으로 예상했나요?”처럼 행동과 생각을 묻는다. 이것도 도움/개입란에 적는다. 위치를 알려주거나 대신 조작했다면 ‘도움 있음’으로 표시한다. 제한 시간으로 실패를 만들지 말고 참여자가 중단하거나 계속하기 어렵다고 할 때 중단 여부를 확인한다.

서버 응답을 기다린 시간과 화면을 이해하지 못해 멈춘 시간을 구분한다. 구분할 근거가 없으면 ‘미확인’으로 적는다. 관찰자의 추측을 실제 발언처럼 인용하지 않는다.

## 진행자용 관찰 기준 — 참여자에게 미리 제공하지 않음

| 과제 | 기록할 근거 |
|---|---|
| 1 | 문제와 할 수 있는 행동을 어떻게 설명하는지, 실제 API와 저장된 실험을 혼동하는지 |
| 2 | 시작 행동을 찾는 과정, 어디서 완료라고 판단하는지, 이전 답변 차단·새 기록·같은 작업 반환을 본인 말로 설명하는지 |
| 3 | 이전 기록을 찾는 과정, 작업 식별/로그를 확인하는지, 복원된 과거 기록을 서버의 현재 재실행으로 오해하는지 |

정해진 단어를 말했는지가 아니라 실제 설명과 행동을 남긴다. 도움 없이 완료/도움 후 완료/미완료/미진행을 구분한다. 결과는 아래 빈 양식을 복사해 작성한다.

## 기록과 수정 연결

[참여자별 빈 기록 양식](usability-record.md)을 사용한다. 사용자에게서 실제 기록을 받은 뒤에만 다음 순서로 진행한다.

1. 과제·화면·실제 발언으로 문제를 식별한다.
2. 서버 대기, 기능 오류, 문구/동선 문제를 구분한다. 원인이 불명확하면 가설로 표시한다.
3. 해당 문구·동선만 수정하고 변경 커밋을 기록한다. 큰 제목은 기능·목적을 나타내는 명사형을 유지한다.
4. 같은 과제를 같은 조건에서 다시 진행한다. 같은 참여자라면 학습 효과가 있음을 기록하고 전후 성공률 개선으로 일반화하지 않는다.

현재 관찰 결과와 그에 따른 UI 변경은 **대기**다. 이번 과거 실험 출처 표시는 기술 자료 대조에 따른 사실 정정이며 사람의 사용성 조사에 따른 개선으로 분류하지 않는다.
