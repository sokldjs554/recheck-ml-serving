# 현재 구현의 설계 선택과 비용

2026-10-19 코드 확인 기준: `fe5df9d84be0c5bb29fcfb9132a4d7dcea15ba1a`. 이번 제출 정리는 아래 백엔드 동작을 변경하지 않는다. 다음 설명은 **현재 코드의 구조와 검증으로 설명 가능한 이유**다. 당시 지원자가 이 대안을 직접 검토·선택했다는 과거 의사결정 기록으로 쓰지 않는다.

## 세션 잠금과 검증·기록

문서 변경과 작업 기록이 동일한 세션 잠금을 사용한다. PostgreSQL에서는 세션 행의 `SELECT … FOR UPDATE`, 로컬 SQLite에서는 `BEGIN IMMEDIATE`로 쓰기를 직렬화한다. `/evidence/.../execute`는 잠금 안에서 같은 키의 기존 작업부터 확인하고, 신규 요청에 대해서만 원문·삭제·만료·릴리스 버전을 확인한 뒤 기록한다.

이 경계는 ‘검사 성공 직후 문서가 변경되고 별도로 기록되는’ 틈을 막는다. 별도 검사 후 기록은 잠금 시간이 짧아 보여도 그 사이 변경을 막지 못한다. 같은 세션의 작업은 기다려야 하고 잠금 시간 초과로 실패할 수 있다. 서로 다른 세션도 같은 DB 연결 풀·CPU·스토리지를 공유하므로 완전히 독립적인 처리 용량을 보장하지 않는다.

## 전체 JSON 상태 저장

`EvidenceState.payload` 하나에 문서, 활성 artifact, 답변, 평가, 이벤트, 작업 목록을 보존한다. `locked()`는 상태 전체를 깊은 복사하고 종료 시 JSON을 다시 할당한다. 작은 가상 사례에서 버전과 작업을 한 트랜잭션으로 일관되게 보존하고 재현하기 쉬운 구조다.

비용은 복사·JSON 직렬화·쓰기 바이트와 잠금 점유다. 현재 `snapshot()`도 같은 잠금/재할당 경로를 이용하므로 조회가 비용 없는 읽기라고 설명하지 않는다. 첫 상태의 검색 artifact 생성은 잠금 안에서, 이후 검색·평가의 주요 계산은 snapshot 밖에서 수행한다. 답변·작업 각 40개, 평가 20개, 이벤트 최근 20개로 범위를 제한한다.

분리 테이블·부분 업데이트는 커진 상태에서 검토할 대안이지만, 여러 행의 버전·키·릴리스 원자성과 마이그레이션을 관리해야 한다. 현재 측정으로 JSON만이 유일한 병목이라고 결론내리지 않았으므로 구조를 교체하지 않았다. 과거 비용 실험은 HTTP 처리량과 구분한다.

## 프로세스 격리

API와 모델 서버는 HTTP로 통신한다. CPU 부하 실험은 모델 서버가 `spawn` 방식 프로세스 풀에 연산을 전달한다. CPU 작업이 이벤트 루프를 오래 점유하는 조건을 분리하고, 모델 프로세스 실패를 추적·차단할 수 있다. 공개 TF-IDF 상담과 이 CPU 실험은 다른 실행 경로다.

비용은 추가 프로세스의 시작 시간·메모리, 모델 복제와 IPC·HTTP 비용이다. 같은 호스트 안의 프로세스 분리는 호스트 장애 격리나 다중 리전 가용성이 아니다. 작은 모델의 무조건적인 속도 향상을 의미하지 않는다. 풀 손상은 재시작이 필요하며 `Execution.unavailable`은 CPython의 `_broken` 감지와 공개 예외 처리를 함께 사용한다.

## 요청 수용 제한과 시간 예산

`Admission`은 실행 슬롯뿐 아니라 대기 요청 수에도 상한을 둔다. 수용 가능한 범위를 넘으면 거절하며, 남은 예산 안에서 슬롯을 얻지 못하면 시간 초과로 끝낸다. CPU 작업 제출 전의 대기는 취소할 수 있지만 제출 후에는 HTTP 요청이 끝나도 작업 소유 task와 슬롯을 실제 종료까지 유지한다. 응답 취소를 처리 용량 반환으로 착각해 작업을 계속 쌓는 상황을 막는다.

비용은 거절·보류되는 요청과 늦은 CPU 작업이 차지하는 슬롯이다. 메모리를 무한히 늘려 요청을 모두 받는 구조도, 제출된 CPU 연산을 즉시 선점 중단하는 구조도 아니다. 한 API/모델 프로세스 안의 제한이며 모든 인스턴스에 걸친 전역 큐가 아니다. 유효 응답·보류·429·504를 같은 분모로 보고, 빠른 거절만으로 p95가 좋아졌다고 주장하지 않는다.

## 저장 후 응답 실패

SQL commit과 클라이언트 응답 수신은 같은 원자적 사건이 아니다. `/decisions`는 저장 후 시간 예산 초과를 확인하면 `504 deadline_exceeded_after_commit`을 반환할 수 있다. 상담 `/evidence/.../execute`도 클라이언트가 연결을 끊었는데 SQL은 완료될 수 있다. 상담의 15초는 관측/브라우저 대기 기준이며 `/decisions`의 시간 예산 정책과 다르다.

응답 실패를 저장 실패로 단정하지 않고 같은 키로 조회·재시도한다. 동일 키의 과거 기록 반환은 신규 실행 또는 현재 근거의 유효성 보장이 아니다. commit 중 DB 오류가 나면 관측의 `storage=unknown`을 보존하고 SQL 기록·재시도로 확인한다. 모든 외부 부수효과의 exactly-once를 보장하는 설계는 아니다.

비용은 키와 기록의 유지, 충돌·pending·불명 상태 처리, 사용자 안내다. `/decisions`의 소유 프로세스가 중단된 미완료 예약은 자동으로 새 추론을 시작하지 않고 새 키가 필요한 상태로 반환한다. 세션 만료 뒤 무제한 재시도/보존은 제공하지 않는다.

## 지원자 역할

지원자는 AI와 주제 후보를 비교한 뒤 주제와 방향을 최종 결정하고, 필요한 기능 추가·범위 조정·구체적인 수정 요구·결과 검토를 수행했다. **코드 작성과 데모 제작은 AI가 주로 담당했다.** 위 구현·실험 설명을 지원자의 직접 설계·코딩·실험 경력으로 바꾸지 않는다.
