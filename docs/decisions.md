# 설계 의사결정

## 1. 점수를 저장하는 것만으로는 충분하지 않다

모델이 읽은 특징 v1을 추론하는 동안 데이터가 v2로 바뀔 수 있다. 추론 직전에만 최신성을 검사하면 오래된 결과가 정상 응답으로 나간다. 따라서 추론 완료 후 저장 직전에 버전을 다시 검사하고, 결과를 다음 단계에서 사용할 때도 확인한다. 검증을 제거한 기준선을 데모에 남겨 같은 문제를 재현한다.

버전 검증은 해당 DB 스냅샷에서 확인한 사실이다. 검증 이후 발생할 모든 미래의 사건, 실제 은행 원장과의 원자성까지 보장하지 않는다. 실거래 시스템이라면 거래의 커밋 경계와 정책을 함께 설계해야 한다.

## 2. 무거운 작업과 요청 수용을 분리한다

API와 모델은 별도 프로세스이며 HTTP로 통신한다. 모델의 수용 가능 작업 수와 대기 수를 제한해 요청이 몰렸을 때 메모리와 지연이 무제한 증가하지 않게 한다. 더 많은 요청을 거절해 p95만 낮아지는 착시를 피하려면 유효 결과 수, 확인 필요 응답, 거절, 오류를 모두 함께 보고해야 한다.

작은 CPU 모델에는 별도 서비스의 네트워크 비용이 더 클 수 있다. 이 분리는 작은 모델의 최대 TPS를 높였다는 주장이 아니라, 모델을 교체할 때 API와 연산 자원의 장애 경계를 관찰하기 위한 선택이다. 분리 전후 성능 우위는 실제 측정 결과가 있을 때만 주장한다.

## 3. 개발과 공유의 비용을 나눈다

정합성 검증용 Compose는 PostgreSQL을 사용한다. 무료 공개 데모는 하나의 호스트에서 API와 모델을 각각 실행하고, 저장소는 싱가포르의 Neon PostgreSQL을 사용한다. 공개 재배포 전후 같은 작업 ID·내용과 멱등 재생을 확인했다. 세션은 설계상 1시간 후 만료되며 무료 호스트의 시작 지연은 남아 있다. PostgreSQL의 다중 인스턴스 운영 검증과 동일한 환경이라고 부르지 않는다. 이 선택으로 면접관은 별도 설치 없이 기능을 확인할 수 있고, 개발자는 전체 구성을 로컬에서 재현할 수 있다.

초기에는 Kafka와 Redis를 추가하지 않는다. 버전 확인과 소량의 판단 기록에 이미 필요한 SQL 저장소로 충분하기 때문이다. 모델 연산과 트래픽 측정이 추가 큐나 캐시의 필요성을 보여줄 때 도입한다.

## 4. AI와 함께 오류를 해결한 경험을 제시한다

지원자는 Python·LLM·AI/ML 경험이 있는 신입이다. 반복되는 오류를 직접 조사하고 AI가 제시한 대안과 자신의 해결 방법을 비교·통합한 경험이 있다. 이 프로젝트의 포트폴리오는 그 과정을 실패 재현, 원인 가설, 대안, 검증으로 보여준다. 실제로 수행하지 않은 대화나 개인 기여는 꾸며내지 않는다. 생성한 코드의 모든 구현을 본인이 이해했다고 미리 주장하지도 않는다.

## 5. 버전 차이를 화면의 주제로 만든다

첫 UI의 사이드바·휴대폰 목업·분리된 카드는 내용을 정리했지만, ‘계산이 끝난 사이 세계가 바뀐다’는 이 프로젝트의 문제를 직접 보여주는 데 약했다. 사용자의 피드백에 따라 화면의 중심을 추론 당시의 버전과 현재 버전의 비교로 바꾼다.

상단 탐색과 한 개의 실험 영역, 변경 신호를 드러내는 주홍색, 기록을 구분하는 청색, 실제 span을 표시하는 가로 타임라인을 사용한다. 아직 판단을 만들지 않은 상태에는 가짜 기록이나 불일치를 표시하지 않는다. 시각적 비교는 실제 receipt·session 상태에서 계산하고, 관측 시간과 개념적 관계를 혼동하지 않게 구분한다. API·시뮬레이션·기존 보호 로직은 유지한다.


## 6. 2026-10-11: 유효성 확인과 내부 작업 기록의 경계

사용 직전 확인은 그 응답 직후의 변경을 막지 못한다. 그래서 기존 `/use`의 의미는 유지하면서,
내부 합성 상담 작업에만 검증과 기록을 같은 DB 트랜잭션으로 처리하는 `/execute`를 추가했다.
외부 메시지·송금을 이 트랜잭션에 포함했다고 주장하지 않는다. HTTP 성공 응답을 잃은 경우에는
같은 요청 키로 과거 작업을 반환하며, 과거 기록 반환을 현재 근거의 재검증으로 오해하지 않도록 구분한다.
[동일 사건 비교](safety-case-study.md)와 [정확한 계약](action-contract.md)에 판단 근거를 남겼다.

UI는 이 사례를 첫 화면으로 선택했다. 기존 여러 실험은 심화 탐색으로 남긴다.
현재 화면은 작은 작업 제목과 상단 탐색, 원문→답변→기록 흐름, 실제 API 사건 기록을 사용한다.
첫 화면에서 모델 부하와 장애 복구의 저장된 실험도 직접 열 수 있다. 사용자 이해도는 실제 참여자 조사를 수행하기 전까지 미검증이다.
