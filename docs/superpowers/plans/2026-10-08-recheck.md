# RECHECK Implementation Plan

> For agentic workers: use subagent-driven-development for independent units and review before integration.

Goal: Deliver a reproducible Python ML backend and a polished Korean interview demo proving inference freshness, bounded latency, and failure diagnosis.

Architecture: FastAPI gateway, independent HTTP inference service, SQLAlchemy persistence with PostgreSQL deployment and SQLite local fallback. React/TypeScript demo consumes the documented API. A clearly labeled deterministic browser simulation also works without backend hosting; it never presents itself as live Python execution.

Tech Stack: Python 3.12, FastAPI, SQLAlchemy, scikit-learn, OpenTelemetry, React, TypeScript, Vite, PostgreSQL, Docker Compose, Kubernetes.

Spec: ../specs/2026-10-08-recheck-design.md

## Global Constraints

- Synthetic data only; no real transfer, real credit decision, fake biography or fabricated metrics.
- UI defaults to explicitly labeled browser simulation until a live API passes health check. It provides a switch to live execution and never silently falls back.
- Actual model inference in Python, bounded queue/concurrency, deadline default 300 ms, feature/model/policy versions and receipt expiry.
- A receipt must be revalidated at use; versions changed during inference cannot produce a valid receipt.
- All changed-state controls are session scoped. Public demo workload and log retention bounded.
- README and UI distinguish measured results, simulation, and deployment configurations not yet exercised.

## Review Focus

- Stale inference completing after feature update must be invalid, including simultaneous requests.
- Request retry with same key and changed body must be 409, not a stale response.
- No late inference task may create unbounded work after gateway timeout.
- Frontend must show disconnected API as an error, not fake success.
- Multiple sessions must not change each other's data or policies.

## Shared API Contract

All routes under /api except /health. JSON field names snake_case. CORS local development only or configured explicitly.

- GET /health -> {status:'ok', service:'recheck-api', mode:'live', model_service: string}
- POST /api/sessions -> {session_id:string, feature_version:1, policy_version:1, model_version:'risk-v1'}
- POST /api/sessions/{id}/decisions body {amount:150000, recipient:'demo-recipient', idempotency_key:uuid, delay_ms:0, fault:'none'|'timeout'|'unavailable', protected:true} -> Receipt
- POST /api/sessions/{id}/mutations body {kind:'feature'|'policy'|'model'} -> {feature_version,policy_version,model_version}
- GET /api/sessions/{id}/decisions -> {receipts:Receipt[]}
- GET /api/sessions/{id}/decisions/{receipt_id}/validate -> {valid:boolean,reason:string,current_versions:{feature_version,policy_version,model_version}}
- GET /api/sessions/{id}/metrics -> {total:number,valid:number,review:number,invalidated:number,p95_ms:number,active:number}

Receipt: {id,session_id,status:'clear'|'review'|'invalidated',reason:string,risk_score:number|null,feature_version:number,policy_version:number,model_version:string,created_at:ISO8601,expires_at:ISO8601,latency_ms:number,trace_id:string,spans:[{name:string,start_ms:number,duration_ms:number,status:'ok'|'error'}],protected:boolean,model_hash:string}

Inference server: POST /infer {features:number[],model_version:string,delay_ms:number,fault:string,deadline_ms:number} -> {risk_score:number,model_version:string,model_hash:string,latency_ms:number}; errors 429/503/504. GET /health.
